# 架构说明（ARCHITECTURE）

> 本文描述实时聊天 Web 应用的整体架构与技术决策。业务模块细节见 [系统设计.md](系统设计.md)。

## 1. 技术栈（已锁定）

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | React 18 + TypeScript + Vite | SPA，开发期由 Vite 代理 `/api`、`/ws` 到后端 |
| 后端 | NestJS 10 + Socket.IO | REST（HTTP）+ WebSocket（实时消息）同进程 |
| 数据库 | MySQL 8 | 业务持久化（用户 / 好友 / 消息） |
| 缓存 / 消息 | Redis 6 | 在线状态、未读计数、会话索引、Pub/Sub 横向扩展预留 |
| 包管理 | npm | 前后端统一 |

## 4. 数据流

- **请求/响应（REST）**：浏览器 → Vite 代理 `/api` → NestJS Controller → Service → MySQL/Redis → 响应。
- **实时消息（WebSocket）**：客户端经 Socket.IO 连接 `/ws` → Gateway → 校验身份 → 写入 MySQL 消息表 + 更新 Redis 未读/在线 → 经 Gateway 推送给对端。
- **多节点扩展（预留）**：当部署多实例时，Gateway 间通过 Redis Pub/Sub 广播消息，保证跨节点投递（见 §6 M1）。

## 5. 已采纳的设计决策

| 编号 | 决策 | 说明 |
|---|---|---|
| B2 | 图片存储：对象存储抽象，先本地磁盘 | 定义 `StorageProvider` 接口，先实现本地磁盘，后续可切 MinIO/云 OSS |
| M1 | 单节点起步，预留 Redis Pub/Sub | 当前单实例即可；消息广播层抽象，便于后续水平扩展 |
| M4 | 双 token（access + refresh）+ 黑名单 | access 短时，refresh 长时；改密/封禁将 refresh 与 jwt id 加入黑名单 |
| 范围 | 本期仅单聊 | 不含群聊、消息撤回、消息编辑 |

## 6. 后续阶段（计划）

- Phase 1：认证（注册/登录/双 token/刷新/登出）
- Phase 2：好友（申请/通过/列表/状态）
- Phase 3：实时通信核心（WebSocket 网关、消息收发、断线补齐）
- Phase 4：单聊历史（分页、拉取）
- Phase 5：在线 / 未读 / 已读
- Phase 6：图片消息（StorageProvider）
- Phase 7：非功能打磨与上线

详见 [需求评审与开发计划.md](需求评审与开发计划.md)。
